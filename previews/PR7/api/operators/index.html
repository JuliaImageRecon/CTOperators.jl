Operators

The generic interface of all CT operators: application with * and mul!, adjoints, sizes, row and column sums, subsets of views, moving to a device with adapt, and the launch configuration of the kernels.

Generic interface

CTOperators.AbstractCTOperator — Type
AbstractCTOperator{T}

Supertype of the CT projection operators of CTOperators.jl. T is the real element type of image and projection data. An operator is created once and applied many times: op * x is the forward projection, adjoint(op) * y the back projection (its adjoint; transpose(op) is the same). op * x returns an array on the operator's device, a vector for a vector x and an array of the data shape otherwise; mul! accepts both shapes.

With LinearOperators.jl loaded, LinearOperators.storage_type(op) is the vector type of the operator's device, so that operators of LinearOperatorCollection.jl take CT operators, e.g. the normal operator normalOperator(op) for the solvers of RegularizedLeastSquares.jl.

source
CTOperators.AbstractProjector — Type
AbstractProjector{T,G<:AbstractProjectionGeometry} <: AbstractCTOperator{T}

Supertype of the projectors of this package: operators between an image on an ImageGeom and projection data of a geometry of type G (stored with its arrays on the device).

Interface:

  • geometry(op)::G, image_geometry(op)::ImageGeom
  • similar_projector(op, geometry): the same kind of projector, with the same image geometry and options, for another geometry (used by subset and adapt); a projector that stores a ray mask also accepts the keyword raymask (default ray_mask(op))
  • the methods of AbstractCTOperator
source
CTOperators.AdjointCTOperator — Type
AdjointCTOperator(op)

The adjoint (back projection) of op, created by adjoint(op); applying it calls backward!(x, op, y).

source
CTOperators.backward! — Function
backward!(x, op::AbstractCTOperator, y)

Back projection (the adjoint) of the projection data y into the image x, overwriting x. Implemented by every operator; users call mul!(x, adjoint(op), y) or adjoint(op) * y.

source
CTOperators.colsums — Method
colsums(op::AbstractCTOperator)

adjoint(op) * ones, the column sums of the system matrix: for every voxel the summed weights of all data elements (the sensitivity image of OS-EM). A normalization of SART/SIRT/OS-EM-type methods.

source
CTOperators.device_geometry — Method
device_geometry(geometry, T, storage)

geometry with its arrays in element type T on the device of storage, an array type such as Array or CuArray (or a concrete one such as CuArray{Float32}). Projector constructors call it with their keywords eltype and storage. Any floating-point type is accepted; below Float32 the ray coordinates lose precision (see Choose the Precision).

source
CTOperators.forward! — Function
forward!(y, op::AbstractCTOperator, x)

Forward projection of the image x (of size imagesize(op)) into y (of size datasize(op)), overwriting y. Implemented by every operator; users call mul!(y, op, x) or op * x.

source
CTOperators.geometry — Function
geometry(op::AbstractProjector)

The projection geometry of op, with its arrays on the device of the operator.

source
CTOperators.image_geometry — Function
image_geometry(op::AbstractProjector)

The ImageGeom the operator was built for.

source
CTOperators.imagesize — Function
imagesize(op)

Size of the operator's input: the image for a projector (2D or 3D, as its ImageGeom), the projection data for its adjoint.

source
CTOperators.rowsums — Method
rowsums(op::AbstractCTOperator)

op * ones: for projectors the length of each ray inside the image (exactly for Siddon's method, approximately for Joseph's). A normalization of SART/SIRT-type methods.

source
CTOperators.similar_projector — Function
similar_projector(op::AbstractProjector, geometry; raymask=ray_mask(op))

A projector of the same kind and with the same image geometry and options as op, for geometry. The keyword raymask exists only for projectors that store a ray mask.

source
CTOperators.subset — Method
subset(op::AbstractProjector, views)

The projector of the views views of op (detector geometries, also with several rays per cell; a vector or range of view indices), for ordered-subset methods. It shares the image geometry and options with op, and the views of its ray mask.

source

Image and ray masks

The image mask comes from the ImageGeom, the ray mask from the keyword raymask of a projector (see Use Masks and Masks). These functions are not exported.

CTOperators.image_mask — Function
image_mask(op) -> Union{Nothing,AbstractArray{Bool}}
ray_mask(op) -> Union{Nothing,AbstractArray{Bool}}

The image mask (the voxels that are reconstructed, of the image size) and the ray mask (the rays that are used, of the data size) of op on its device, nothing without a mask.

source
CTOperators.ray_mask — Function
image_mask(op) -> Union{Nothing,AbstractArray{Bool}}
ray_mask(op) -> Union{Nothing,AbstractArray{Bool}}

The image mask (the voxels that are reconstructed, of the image size) and the ray mask (the rays that are used, of the data size) of op on its device, nothing without a mask.

source
CTOperators.handles_raymask — Function
handles_raymask(op) -> Bool

Whether op applies its ray mask itself (masked rays give 0 in the forward projection and add nothing in the back projection); otherwise the generic layer multiplies by the mask. Default false; the projectors of this package define it as true and skip masked rays in their kernels.

source

Launch configuration

CTOperators.LaunchConfig — Type
LaunchConfig(; workgroupsize=nothing, tile=nothing)

How a projector launches its kernels (forward and back projection), for tuning on a particular device. Pass it to a projector with the keyword launch.

  • workgroupsize: the number of threads (work-items) per workgroup, nothing for the choice of KernelAbstractions.jl.
  • tile: (tu, tv) to let the threads of a workgroup take the rays of tiles of tu × tv detector cells instead of consecutive cells of a detector row (detector geometries only; ray lists keep their order), nothing for data order. Tiles at the edges of the detector are padded with idle threads; a workgroup size of tu * tv gives one tile per workgroup.

Without launch (or with launch=nothing) a projector takes the defaults of its device, also after adapt to another device: on GPUs workgroups of 64 and tiles of 8 × 8 cells, on the CPU data order and the backend's workgroups.

The GPU defaults were tuned on one AMD GPU; tune them for yours. See the explanation page Workgroups and Ray Order on GPUs in the documentation.

Example

using CUDA
launch = LaunchConfig(; workgroupsize=128, tile=(16, 8))
op = JosephProjector(image, geometry; storage=CuArray, launch)

Extensions

  • With LinearOperators.jl loaded, normalOperator(op) of LinearOperatorCollection.jl gives the normal operator AᵀA of a CT operator, e.g. for AHA of the solvers of RegularizedLeastSquares.jl. With LinearOperatorCollection.jl loaded, the normal operator of the projectors of this package runs in one pass over the rays, also with weights (see Normal Operator).
  • With ChainRulesCore.jl loaded, the operators are differentiable (see Differentiate through a Projector).
  • With Sinograms.jl loaded, its geometries are converted by projection_geometry (see Use Geometries of Sinograms.jl).
