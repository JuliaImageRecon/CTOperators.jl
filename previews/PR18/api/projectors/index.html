Projectors

The projectors of the package, all with an exact adjoint. Siddon and Joseph trace the rays of a geometry through the voxel grid, one per detector cell or several with MultiRay; Siddon's Method and Joseph's Method explain how they weight the voxels. The distance-driven method integrates over the area of each detector cell, and the voxel-driven method projects each voxel onto the detector; both need a detector geometry. System Matrix describes what they have in common.

Siddon

CTOperators.SiddonProjector — Type
SiddonProjector(image::ImageGeom, geometry; eltype=Float32, storage=Array, launch=nothing, raymask=nothing)

Projector with Siddon's method: the weight of a voxel for a ray is the exact length of the ray inside the voxel (Siddon 1985), computed incrementally as in Jacobs et al. 1998. Works with every AbstractProjectionGeometry. The back projection is the exact adjoint.

Keywords:

  • eltype is the element type of the computation and of the stored geometry.
  • storage is the array type that selects the device (Array, CuArray, ROCArray, …). Image and projection data passed to the operator must live on that device.
  • launch is a LaunchConfig to tune the kernel launches for a device, nothing for the defaults of the device.
  • raymask is nothing or an array with one entry per data element, of the data size (raymask[u, v, view]) or a vector, on any device: the data elements that are used (true). It is stored as Bool on the device of the operator. Masked data elements give 0 in the forward projection and contribute nothing to the back projection.

The mask of image (e.g. ImageGeom(MaskCircle(); dims, deltas), the circular field of view) selects the voxels: voxels outside count as 0 in the forward projection and get 0 in the back projection, and the rays are only traced through the bounding box of the image mask. See Use Masks.

Example

image = ImageGeom(; dims=(128, 128, 64), deltas=(1, 1, 1))
geometry = circular_cone_beam(; angles=range(0, 2pi, 361)[1:360], dso=500, dsd=1000,
                              nu=256, nv=128, du=1, dv=1)
op = SiddonProjector(image, geometry)
x = rand(Float32, 128, 128, 64)
y = op * x                 # forward projection, size (256, 128, 360)
z = adjoint(op) * y        # back projection

References:

  • R. L. Siddon, "Fast calculation of the exact radiological path for a three-dimensional CT array", Med. Phys. 12(2), 252–255, 1985.
  • F. Jacobs, E. Sundermann, B. De Sutter, M. Christiaens, I. Lemahieu, "A fast algorithm to calculate the exact radiological path through a pixel or voxel space", J. Comput. Inf. Technol. 6(1), 89–94, 1998.

Joseph

CTOperators.JosephProjector — Type
JosephProjector(image::ImageGeom, geometry; eltype=Float32, storage=Array, launch=nothing, raymask=nothing)

Projector with Joseph's method (Joseph 1982): the image is interpolated bilinearly within each layer of voxels perpendicular to the axis the ray runs most along (its principal axis), and the line integral is the sum over the layers of the interpolated value times the length of the ray in the layer. Compared with SiddonProjector:

  • the image model is smooth, so the projection changes continuously when a ray moves;
  • for one parallel-beam view with cells as wide as the voxels, the rays cover the voxels more evenly, except near 45°, where the two methods give similar weights;
  • the projection is exact for images that are linear functions of the position rather than for voxel images.

Works with every AbstractProjectionGeometry. The back projection is the exact adjoint.

Outside the volume the image is zero; across the ray it fades to zero up to half a voxel beyond the faces of the volume. If a segment starts or ends inside the volume, only the part of the end layer it actually crosses is counted.

Keywords:

  • eltype is the element type of the computation and of the stored geometry.
  • storage is the array type that selects the device (Array, CuArray, ROCArray, …). Image and projection data passed to the operator must live on that device.
  • launch is a LaunchConfig to tune the kernel launches for a device, nothing for the defaults of the device.
  • raymask is nothing or an array with one entry per data element, of the data size (raymask[u, v, view]) or a vector, on any device: the data elements that are used (true). It is stored as Bool on the device of the operator. Masked data elements give 0 in the forward projection and contribute nothing to the back projection.

The mask of image (e.g. ImageGeom(MaskCircle(); dims, deltas), the circular field of view) selects the voxels: voxels outside count as 0 in the forward projection and get 0 in the back projection, and the rays are only traced through the bounding box of the image mask. See Use Masks.

Example

image = ImageGeom(; dims=(128, 128, 64), deltas=(1, 1, 1))
geometry = circular_cone_beam(; angles=range(0, 2pi, 361)[1:360], dso=500, dsd=1000,
                              nu=256, nv=128, du=1, dv=1)
op = JosephProjector(image, geometry)
x = rand(Float32, 128, 128, 64)
y = op * x                 # forward projection, size (256, 128, 360)
z = adjoint(op) * y        # back projection

Reference:

  • P. M. Joseph, "An improved algorithm for reprojecting rays through pixel images", IEEE Trans. Med. Imaging 1(3), 192–196, 1982.

Distance-Driven

CTOperators.DistanceDrivenProjector — Type
DistanceDrivenProjector(image::ImageGeom, geometry; eltype=Float32, storage=Array, launch=nothing, raymask=nothing)

Projector with the distance-driven method (De Man & Basu 2004), which integrates over the detector cells instead of following single rays. Per view the image is cut into layers perpendicular to the principal axis of the view, the axis along which the view's central ray (from the source through the detector center) advances most. In every layer, the edge rays through the midpoints of the four edges of a detector cell span a rectangle, the cell's footprint; the cell measures the mean of the image over the footprint times the length per layer of its ray, summed over the layers. The footprints of neighboring cells share their edges and cover each layer without gaps. The back projection is the exact adjoint. See Distance-Driven Method and System Matrix.

Works with detector geometries (AbstractDetectorGeometry: ConeBeam, ArcConeBeam, ParallelBeam), not with ray lists, which have no detector cells, nor with a MultiRay: the footprint already covers the whole cell. For a 2D image the footprint extends only within the image plane.

Keywords:

  • eltype is the element type of the computation and of the stored geometry.
  • storage is the array type that selects the device (Array, CuArray, ROCArray, …). Image and projection data passed to the operator must live on that device.
  • launch is a LaunchConfig to tune the kernel launches for a device, nothing for the defaults of the device.
  • raymask is nothing or an array with one entry per data element (detector cell and view), of the data size (raymask[u, v, view]) or a vector, on any device: the cells that are used (true). It is stored as Bool on the device of the operator. Masked data elements give 0 in the forward projection and contribute nothing to the back projection.

The mask of image (e.g. ImageGeom(MaskCircle(); dims, deltas), the circular field of view) selects the voxels: voxels outside count as 0 in the forward projection and get 0 in the back projection, and the layers are limited to the bounding box of the image mask. See Use Masks.

Example

image = ImageGeom(; dims=(128, 128, 64), deltas=(1, 1, 1))
geometry = circular_cone_beam(; angles=range(0, 2pi, 361)[1:360], dso=500, dsd=1000,
                              nu=256, nv=128, du=1, dv=1)
op = DistanceDrivenProjector(image, geometry)
x = rand(Float32, 128, 128, 64)
y = op * x                 # forward projection, size (256, 128, 360)
z = adjoint(op) * y        # back projection

References:

  • B. De Man, S. Basu, "Distance-driven projection and backprojection in three dimensions", Phys. Med. Biol. 49(11), 2463–2475, 2004.
  • R. Liu, L. Fu, B. De Man, H. Yu, "GPU-based branchless distance-driven projection and backprojection", IEEE Trans. Comput. Imaging 3(4), 617–632, 2017.

Voxel-Driven

The projector and its scales: how the bilinear weights of a voxel are scaled per view (see Voxel-Driven Method).

CTOperators.AbstractVoxelScale — Type
AbstractVoxelScale

How a VoxelDrivenProjector scales the bilinear weights of a voxel in a view: the weight of voxel j in cell i is voxel_scale(scale, geometry, k, grid, hit) times the bilinear weight of cell i at the point where voxel j projects (hit, from project_point). Subtypes: LineIntegralScale (the default) and UnitScale. A new scale is a subtype with a method of voxel_scale; it must be usable inside kernels (an isbits struct).

source
CTOperators.LineIntegralScale — Type
LineIntegralScale()

The default scale of a VoxelDrivenProjector: the forward projection approximates the mean of the line integrals over each detector cell, the detector model of the distance-driven method. A voxel of volume V projecting with density ρ (see project_point) gets the scale V ρ: its forward projection, integrated over the detector area, is V (R / r)² / cos φ, what the line integrals through a point mass V give (when all its cells lie on the detector). See Voxel-Driven Method for the derivation.

For a 2D image (one voxel thick in z) the line integrals run within the image plane: the scale is A (R / r) / (Δu cos φ) with A the pixel area and Δu the cell width, and every detector row whose ray passes within the thickness of the image at the position of the pixel gets the full weight (no averaging along v).

source
CTOperators.UnitScale — Type
UnitScale()

A scale of 1 for a VoxelDrivenProjector: the weights are the bilinear interpolation weights alone, without the voxel volume, the magnification or the obliquity of the ray. The forward projection then no longer approximates line integrals; the back projection is plain interpolation of the data, for methods that apply their own weights.

source
CTOperators.VoxelDrivenProjector — Type
VoxelDrivenProjector(image::ImageGeom, geometry; scale=LineIntegralScale(), eltype=Float32, storage=Array, launch=nothing, raymask=nothing)

Projector with the voxel-driven method (the pixel-driven method of De Man & Basu 2004): in every view, the center of each voxel is projected from the source (along the direction for parallel beams) onto the detector, and the voxel contributes to the 2 × 2 cells around that point with bilinear weights, times a scale (keyword scale, an AbstractVoxelScale). The back projection is the exact adjoint, the way implementations of filtered back projection usually back project, with the weights of the scale. See Voxel-Driven Method and System Matrix. Compared with the ray-driven projectors:

  • the back projection runs one thread per voxel and writes each voxel once, without atomic additions, so repeated back projections are equal; every voxel is covered, whatever the cell size;
  • the forward projection adds into the data with atomic additions, and with cells (at the object) smaller than the voxels it shows a pattern at the scale of the cells, the high-frequency artifacts of De Man & Basu (2004).

For a 2D image the cells are interpolated along u only: every detector row whose ray passes within the thickness of the image at the position of a pixel gets two cells with the full weight.

Works with detector geometries (AbstractDetectorGeometry: ConeBeam, ArcConeBeam, ParallelBeam), not with ray lists, which have no detector to project onto, nor with a MultiRay.

Keywords:

  • scale: LineIntegralScale (the default: the forward projection approximates line integrals, like the other projectors), UnitScale, or a scale of your own.
  • eltype is the element type of the computation and of the stored geometry.
  • storage is the array type that selects the device (Array, CuArray, ROCArray, …). Image and projection data passed to the operator must live on that device.
  • launch is a LaunchConfig to tune the kernel launches for a device, nothing for the defaults of the device; only its workgroup size applies (the threads take the voxels in order).
  • raymask is nothing or an array with one entry per data element (detector cell and view), of the data size (raymask[u, v, view]) or a vector, on any device: the cells that are used (true). It is stored as Bool on the device of the operator. Masked data elements give 0 in the forward projection and contribute nothing to the back projection.

The mask of image (e.g. ImageGeom(MaskCircle(); dims, deltas), the circular field of view) selects the voxels: voxels outside count as 0 in the forward projection and get 0 in the back projection; the threads cover the bounding box of the mask. See Use Masks.

Example

image = ImageGeom(; dims=(128, 128, 64), deltas=(1, 1, 1))
geometry = circular_cone_beam(; angles=range(0, 2pi, 361)[1:360], dso=500, dsd=1000,
                              nu=256, nv=128, du=1, dv=1)
op = VoxelDrivenProjector(image, geometry)
x = rand(Float32, 128, 128, 64)
y = op * x                 # forward projection, size (256, 128, 360)
z = adjoint(op) * y        # back projection

References:

  • B. De Man, S. Basu, "Distance-driven projection and backprojection in three dimensions", Phys. Med. Biol. 49(11), 2463–2475, 2004 (the pixel-driven method, its weight factors and artifacts).
  • W. Zhuang, S. S. Gopal, T. J. Hebert, "Numerical evaluation of methods for computing tomographic projections", IEEE Trans. Nucl. Sci. 41(4), 1660–1665, 1994.
